# Changelog

All notable changes to this project will be documented in this file.

## [2.2.6] - 2026-11-05

### Changed
- **Bore tunnel client is now built in** - The tunnel protocol (null-delimited JSON control frames + raw TCP data streams) is implemented natively in Go; the external `bore` binary is no longer downloaded at runtime
  - Single binary: nothing is fetched, dropped to disk, or executed as a child process at startup — the runtime download-and-execute pattern that antivirus heuristics (e.g. Windows Defender) flag as dropper behavior is gone
  - Instant tunnel startup (no download/extract step)
  - Verified end-to-end against the live bore.pub service, including TLS through the tunnel
  - `-bore-path` is now deprecated and ignored (kept so existing scripts don't break)

## [2.2.5] - 2026-11-05

### Changed
- **Secure defaults** - Running with no switches now enables the bore tunnel and HTTPS (auto-generated self-signed certificate); previously the server started plain-HTTP and tunnel-less
  - `-tunnel` defaults to `bore` (disable with `-tunnel=` for pure LAN use)
  - `-tls-selfsigned` defaults to `true` (disable with `-tls-selfsigned=false`, or use `-tls-cert`/`-tls-key` for real certificates)
  - With `-tunnel cloudflare`, the auto-generated local TLS is skipped automatically (the Cloudflare edge serves HTTPS and expects a plain loopback origin); explicit `-tls-cert`/`-tls-key` are still honored
- **User manual updated** to v2.2.5: corrected cover version, new defaults documented, layout verified (no split figures, no header/footer collisions)

## [2.2.4] - 2026-11-05

### Added
- **Native HTTPS/TLS support** - The server can now serve HTTPS directly, so evidence, credentials, and the admin token are encrypted end-to-end regardless of the transport below (bore tunnels are plaintext TCP by design)
  - `-tls-cert` / `-tls-key` flags (`TLS_CERT`/`TLS_KEY` config keys) for real certificates
  - `-tls-selfsigned` flag: zero-config auto-generated self-signed certificate, stored under `<storage>/.tls/` and reused across restarts (stable browser exception)
  - Self-signed certificate covers `localhost`, `127.0.0.1`, `::1`, the machine hostname, and `-external-ip`; its SHA-256 fingerprint is printed at startup for out-of-band verification
  - Generated links (upload links, triage links, auto-open URL) automatically use `https://` when TLS is enabled
  - Startup fails fast when only one of `-tls-cert`/`-tls-key` is given

### Changed
- Documentation now recommends pairing bore tunnels with TLS instead of avoiding them

## [2.2.3] - 2026-11-04

### Fixed
- **CoC PDF footer showed the wrong software version** - The footer hardcoded "Generated by Evidence Upload v2.0.0" instead of the running version; the version is now threaded through from `version.go`, so the Chain of Custody document records the correct generator version
- **CoC PDF garbled non-Latin-1 text** - Case descriptions, analyst names and filenames containing em-dashes, umlauts, Cyrillic etc. rendered as mojibake (core PDF fonts are Latin-1 only); the PDF now renders real UTF-8
- **CoC generation failed on emoji** - With UTF-8 fonts, unsupported characters would abort the document with "character outside the supported range"; they are now marked with `�` instead

### Added
- **Embedded DejaVu Sans fonts** (regular/bold/oblique/mono) in the CoC generator for full Unicode rendering — Bitstream Vera license, bundled under `internal/custody/fonts/`
- **Font-coverage-aware text sanitizer** - The renderable set is derived from the fonts' own cmap tables (dependency-free TTF parser); `truncate` and hash display are now rune-safe
- **CoC regression tests** - BMP codepoint sweep through every PDF text position, sanitizer unit tests, hostile-input battery

## [2.2.2] - 2026-11-04

### Security
- **Admin API now requires an admin token** - Previously the admin API was fully unauthenticated, so anyone who could reach the server (e.g. through a bore/Cloudflare tunnel) could list sessions, steal upload links, create/revoke sessions, and upload triage packages
  - Token is auto-generated at startup and printed to the console (override with `-admin-token` or `ADMIN_TOKEN`)
  - Sent as `X-Admin-Token` header (or `Authorization: Bearer`); the admin panel prompts once and stores it in `sessionStorage`
  - The auto-opened admin URL carries `?key=<token>` for seamless startup (removed from the address bar after load)
  - Constant-time token comparison; fails closed if no token is configured
- **Upload secrets removed from the session list API** - `GET /admin/api/sessions` no longer returns `secret` values; a leaked list can no longer be turned into working upload links (the per-session detail endpoint still provides the secret for building a link)
- **Request logging shows the method, path, status and duration** - Query strings are omitted so tokens/secrets never reach logs

### Added
- **`-admin-token` flag / `ADMIN_TOKEN` config key**
- **Startup prints the admin token** (override recommended for shared/documented deployments)

### Fixed
- **Auto-open browser URL when `BaseURL` is empty** - Falls back to `http://localhost:<port>/admin` instead of opening a bare path

## [2.2.1] - 2026-11-04

### Added
- **Live admin panel updates** - Sessions table and open session detail now auto-refresh every 5 seconds
  - Upload counter and total size update without page reload
  - "updated" timestamp indicator; refresh pauses while the browser tab is hidden
- **File names and hashes in admin panel** - Sessions table lists every uploaded file with its SHA-256
  - Session detail shows the full 64-character SHA-256 per file with a copy button
- **Unix release archives** - Linux/macOS builds are now shipped as `.tar.gz` so the executable bit survives download (bare binaries downloaded over HTTP lose it and fail with "permission denied")

### Fixed
- **Admin panel "Load failed" on revoke / stale data** - Root cause: admin APIs returned live session pointers while uploads mutated them
  - The resulting data races could corrupt or abort in-flight admin responses, which browsers surface as an opaque "Load failed" / "Failed to fetch" on the next request
  - `GetSession`/`GetSessionDetail`/`ListSessions` now return deep-copy snapshots; all mutation happens inside `SessionManager` under its lock
- **Session folder names capped at 64 chars** - Long descriptions caused `mkdir ...: file name too long` and silently failed CoC generation
- **CoC generation serialized** - A manual revoke racing the expired-session cleanup could interleave writes to the same `CHAIN_OF_CUSTODY.pdf`
- **XSS via uploaded filenames in admin panel** - All uploader-controlled strings are now HTML-escaped before rendering
- **Clipboard copy over plain HTTP** - Copy buttons use a fallback where `navigator.clipboard` is unavailable (non-HTTPS contexts)

### Changed
- **Request logging** - Every request is logged as `METHOD /path -> status (duration)`; query strings are omitted so tokens/secrets never reach logs
- **Panic recovery** - Handler panics are logged with a stack trace and returned as a JSON 500 instead of silently killing the connection
- **Actionable admin errors** - Admin API errors return JSON; the UI distinguishes "server unreachable" from "server returned an error" instead of showing "Load failed"
- **Regression test** - Fuzz-style CoC test covering hostile descriptions/analyst names (parens, control chars, emoji, RTL, truncation boundaries)

## [2.2.0] - 2026-08-11

### Added
- **Triage collection package support** - Analysts can upload a triage package via the admin panel
  - "Send Triage Package" button in session detail modal
  - File picker for selecting the triage package
  - Public download link generated: `http://host:8443/triage/<token>`
  - Link can be shared with remote parties for file download
  - Package replace option for updating existing triage packages
- **Auto-open browser** - Application automatically opens admin interface on startup
  - Opens `http://localhost:8443/admin` in default browser
  - Platform-specific browser open (macOS: `open`, Linux: `xdg-open`, Windows: `cmd /c start`)
  - Use `-no-browser` flag to disable auto-open

## [2.1.1] - 2026-08-10

### Added

  - "Send IP Info" button uploads browser-generated IP detection report as evidence
  - Upload form disabled until IP info is sent
  - IP info file parsed by Chain of Custody PDF for detailed collector IP section

### Fixed

### Changed

## [2.1.0] - 2026-08-10

### Added
- **Chain of Custody PDF generation** - Automatic forensic documentation when sessions end
  - PDF generated on session revocation with analyst name prompt
  - PDF generated for expired sessions (background cleanup every 5 minutes)
  - Includes: case info, evidence items with SHA-256 hashes, activity timeline, integrity verification, signature block
  - Saved as `CHAIN_OF_CUSTODY.pdf` in the case folder with `.sha256` sidecar
- **Revoke modal with analyst name** - Admin panel prompts for analyst name before revoking
- **Session expiration cleanup** - Background goroutine now properly cleans up expired sessions

### Changed
- `RevokeSession()` now returns the session object before deletion (enables CoC generation)
- `CleanupExpired()` now returns list of expired sessions (enables CoC generation for expired sessions)

## [2.0.0] - 2026-08-07

### Added
- **Cloudflare Tunnel support** - Full integration with Cloudflare tunnels
  - `-tunnel cloudflare` flag for Cloudflare tunnel mode
  - `-tunnel-token` flag for token-based authentication
  - Auto-install cloudflared binary
  - Named tunnel support
  - Custom domain support (e.g., yourdomain.com)
- **Multi-analyst mode** - `-tunnel external` for centralized tunnel deployment
  - Domain owner runs tunnel, analysts just use the URL
  - No cloudflared needed on analyst machines
- **Config file support** - `~/.evidence-upload.conf`
  - All settings can be stored in config file
  - Environment variable override with `EVIDENCE_*` prefix
  - Secure file permissions (chmod 600)
- **Incident-based folder naming** - Upload folders named after case/incident
  - Folders use sanitized description (e.g., `INC-2024-001/`)
  - Original token-based folders still supported
- **Filename sanitization** - Spaces and symbols replaced with underscores
  - `My Evidence (1).exe` → `My_Evidence_1.exe`
- **SHA-256 hash files** - Written after each successful upload
  - Compatible with `sha256sum -c` verification
  - Format: `hash  filename`
- **IP detection** - Shows both local and public IP on upload page
  - Public IP fetched from api.ipify.org
  - Download IP info as text file for documentation
- **IP detection endpoint** - `/api/my-ip` returns client IP details

### Changed
- Upload folders now use incident name instead of token hash
- Improved IP parsing for IPv6 addresses
- Updated README with Cloudflare Tunnel documentation

### Fixed
- `fmt.Fprintf` CSS/JS escaping bug
- `GetSession()` deadlock (removed delete under RLock)
- `handleUploadFile` ParseMultipartForm order
- bore binary path resolution for relative paths
- bore public port detection from stdout
